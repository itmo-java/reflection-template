# Лабораторная работа № 2. Java Reflection — генератор объектов

## Цель

Познакомиться с Java Reflection API и научиться использовать информацию о типах во время выполнения программы. Спроектировать генератор случайных значений и объектов, работающий не только с заранее известными классами.

## Задание

Реализуйте генератор, которому можно передать `Class<?>` требуемого типа и получить значение этого типа. Примеры запросов:

```java
Integer number = generateValueOfType(Integer.class);
String text = generateValueOfType(String.class);
Rectangle rectangle = generateValueOfType(Rectangle.class);
Shape shape = generateValueOfType(Shape.class);
int[] numbers = generateValueOfType(int[].class);
List<?> items = generateValueOfType(List.class);
Map<?, ?> entries = generateValueOfType(Map.class);
```

Это примеры использования, а не обязательная сигнатура метода. Вы можете выбрать собственный API, но должна сохраняться возможность запросить значение по `Class<?>`.

Используйте `java.lang.reflect` для исследования пользовательских типов и создания их экземпляров. Для генерации случайных значений примитивных типов и строк используйте `java.util.Random`.

Классы в пакете `classes` задают ориентир по сложности объектов. **Нельзя подменять универсальную генерацию набором специальных веток, рассчитанных исключительно на имена классов из шаблона.** Генератор должен работать и с новыми классами сопоставимой сложности.

## Обязательные возможности

### Поддерживаемые типы

| Категория | Примеры |
| --- | --- |
| Примитивные типы и их обёртки | `int`, `double`, `boolean`, `char`, `Integer`, `Double` и др.  |
| Строки | `String` |
| Перечисления | `enum Color { RED, GREEN, BLUE }` |
| Массивы | `int[]`, `String[]`, `Color[]`, `Rectangle[]` |
| Списки | `List` (хотя бы один поддерживаемый вариант списка) |
| Отображения | `Map` (хотя бы один поддерживаемый вариант отображения) |
| Пользовательские классы | `Rectangle`, `Triangle` и новые классы аналогичной сложности |
| Интерфейсы и абстрактные классы | `Shape` и другие типы с подходящими реализациями |

Для массивов обязательна поддержка как минимум одномерных массивов с элементами поддерживаемых типов. Для `List` и `Map` достаточно продемонстрировать генерацию **хотя бы одного непустого варианта** каждого вида, содержащего сгенерированные элементы и пары ключ–значение соответственно. Поддержка всех разновидностей коллекций и произвольных сочетаний generic-типов **не требуется**. Выбранные ограничения опишите в своём решении.

Размеры массивов и коллекций, диапазоны и распределения случайных значений, длины строк и прочие параметры генерации определяются студентом. Генерация не должна сводиться к постоянному возвращению одной заглушки. Генерация `void`/`Void` не требуется.

### Пользовательские объекты

Генератор должен создавать объекты пользовательских классов с применением Reflection API. Способ создания и заполнения объектов, а также выбор конструкторов остаются на усмотрение студента.

Помимо классов из шаблона, решение должно поддерживать новые подходящие классы без добавления отдельных проверок на их имена, а также классы из пакета `classes`, включая возможность запросить генерацию по `Shape.class`. В результате такого запроса должен получиться объект, совместимый с `Shape`. Аналогичное требование относится к поддерживаемым абстрактным классам.

### Аннотация `@Generatable`

Разработайте собственную аннотацию `@Generatable` и используйте её в работе генератора. Аннотация должна иметь **реальное значение для логики программы**, а не присутствовать только формально.

Правила её применения и интерпретации студент выбирает самостоятельно. В README своего решения необходимо объяснить выбранную семантику, в том числе для интерфейсов, абстрактных классов и их реализаций.

### Ошибки генерации

Если запрос невозможно обработать, генератор должен завершаться **осмысленным исключением**, по которому можно понять причину неудачи. Возврат `null` как универсальный признак ошибки не допускается.

# Решение

## Как пользоваться

Один вход — `Generator.generate`. Тип можно передать явно или не передавать вовсе: тогда он выводится из переменной, которой присваивается результат.

```java
Generator generator = new Generator();            // или new Generator(new Random(42)) для воспроизводимости

Integer number = generator.generate(Integer.class);
Shape shape = generator.generate(Shape.class);
List<?> items = generator.generate(List.class);

Rectangle rectangle = generator.generate();        // тип выведен из присваивания
int[] numbers = generator.generate();
```

Вывод типа работает через пустой varargs-массив `T...`: Java создаёт массив выведенного типа `T`, и его тип элементов доступен во время выполнения. Generic-аргументы при этом стираются: `List<Product> list = generator.generate()` будет заполнен строками. Для generic-полей и параметров конструкторов это не так: там тип берётся из сигнатуры (`getGenericParameterTypes`), поэтому `Cart` получает `List<Product>`.

## Архитектура

```
generator/
├── Generator             единая точка входа, список генераторов типов
├── TypeGenerator         интерфейс генератора одной категории типов: supports(Class) + generate(Type, context)
├── GenerationContext     Random, текущая глубина, генерация вложенных значений, размеры коллекций
├── Types                 работа с java.lang.reflect.Type: стёртый класс, generic-аргументы
├── Generatable           аннотация
├── GenerationException   единственный тип ошибки генерации
├── primitive/            PrimitiveGenerator + по классу на каждый примитив (int и Integer — один генератор)
├── simple/               StringGenerator, EnumGenerator
├── collection/           ArrayGenerator, ListGenerator, MapGenerator
└── object/               ObjectGenerator (конструкторы), AbstractTypeGenerator (интерфейсы и абстрактные классы),
                          ImplementationScanner (поиск реализаций на classpath)
```

`Generator` проходит по списку `TypeGenerator` и отдаёт запрос первому, который поддерживает тип. Вложенные значения (аргументы конструкторов, элементы массивов и коллекций) генерируются через `GenerationContext.generate(Type)`, то есть тем же путём, что и запрос верхнего уровня. Поэтому любые сочетания поддерживаемых типов работают сами собой.

Расширение — новый `TypeGenerator` без правок существующего кода:

```java
List<TypeGenerator> generators = new ArrayList<>(Generator.defaultGenerators());
generators.addFirst(new MyGenerator());           // раньше стоящий генератор имеет приоритет
Generator generator = new Generator(new Random(), generators);
```

## Семантика `@Generatable`

| Где стоит | Что означает |
| --- | --- |
| На конкретном классе | Генератору разрешено создавать экземпляры класса. Без аннотации — `GenerationException`, даже если у класса есть подходящий конструктор. |
| На конструкторе | Генератор выбирает только среди помеченных конструкторов, в том числе не публичных. Если помеченных нет — среди всех публичных. Конструктор выбирается случайно. |
| Интерфейс / абстрактный класс | Аннотация на них не нужна и ни на что не влияет: создать их нельзя. При запросе такого типа генератор берёт случайную реализацию **с `@Generatable`**. Реализации без аннотации не рассматриваются. |

Аннотация на конструкторе без аннотации на классе не делает класс генерируемым: класс должен быть помечен сам.

Типы JDK (`String`, обёртки, `List`, `Map` и т.п.) обрабатываются своими генераторами и аннотации не требуют.

## Поддерживаемые типы и параметры

| Категория | Как генерируется |
| --- | --- |
| `boolean`, `byte`, `short`, `char`, `int`, `long`, `float`, `double` и обёртки | `int` в `[-1000, 1000]`, `long` в `[-10⁶, 10⁶]`, `float`/`double` в `[-1000, 1000)`, `char` — `a..z`, `byte`/`short` — весь диапазон |
| `String` | 1–10 символов из `[a-zA-Z0-9]` |
| `enum` | случайная константа |
| Массивы | любой размерности, 1–5 элементов |
| `List`, `ArrayList` | `ArrayList`, 1–5 элементов |
| `Map`, `HashMap` | `HashMap`, 1–5 пар (при совпадении ключей пар меньше, но хотя бы одна есть) |
| Пользовательские классы | через конструктор, аргументы генерируются по их generic-типам; records тоже поддерживаются |
| Интерфейсы и абстрактные классы | случайная реализация с `@Generatable` |

## Ограничения

- Реализации интерфейсов и абстрактных классов ищутся сканированием classpath **в пакете абстрактного типа и его подпакетах** (каталоги и jar). Реализации из других пакетов не находятся. У интерфейсов JDK (`Runnable` и т.п.) реализаций не находится, будет `GenerationException`.
- Если тип элементов коллекции неизвестен (`List.class`, `List<?>`, `List<T>`), элементы — строки (`Types.DEFAULT_ELEMENT_TYPE`).
- Из коллекций поддерживаются только `List` и `Map` (реализации `ArrayList` и `HashMap`). `Set`, `Queue`, `Collection` не поддерживаются.
- Объекты создаются только через конструктор, поля после создания не заполняются.
- Рекурсивные структуры обрываются по глубине: на глубине больше `GenerationContext.MAX_DEPTH = 5` вместо пользовательского объекта подставляется `null` (так у `BinaryTreeNode` появляются листья). Это единственный случай `null`, на верхнем уровне `null` не возвращается никогда.
- Если не задать `Random` в конструкторе `Generator`, значения при каждом запуске разные.

## Ошибки

Все ошибки — `GenerationException` с понятной причиной в сообщении:

- класс не помечен `@Generatable`, в том числе вложенный (сообщение называет именно его);
- у класса нет ни публичных конструкторов, ни конструкторов с `@Generatable`;
- конструктор выбросил исключение (исходное исключение — в `getCause()`);
- нет реализаций интерфейса или абстрактного класса с `@Generatable`;
- `enum` без констант;
- неподдерживаемый тип (`void` и т.п.);
- тип не удалось вывести (`Object value = generator.generate()`).
